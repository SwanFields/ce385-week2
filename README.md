ex1-profile.js
ประกาศตัวแปรข้อมูลส่วนตัว 5 อย่าง (ชื่อเล่น, รหัสนักศึกษา, อายุ, สาขา, จำนวนวิชาที่ลง) ด้วย const เพราะค่าไม่เปลี่ยน 
แล้วใช้ Template Literal พิมพ์ออกมาเป็นบัตรแนะนำตัวสวยๆ ในบรรทัดเดียว
แทนที่จะต้อง + ต่อสตริงหลายๆทีและการคำนวณปีที่จะจบอยู่ในตัว template ด้วย

ex2-types.js
ประกาศตัวแปรครบ 6 ชนิดข้อมูลของ JS (string, number, boolean, undefined, null, array) แล้วใช้ typeof เช็คชนิดของแต่ละตัว
จุดที่น่าสนใจคือทดสอบ 3 เคสคลาสสิกของ JS: typeof null ที่ผิดกฎ, ตัวแปรที่ยังไม่กำหนดค่าจะเป็น undefined, และ typeof NaN จะได้ "number" (เพราะ NaN ถือเป็นตัวเลขชนิดหนึ่งใน JS)
แปลงชนิดข้อมูลด้วย Number() เพื่อเปลี่ยน string เป็นตัวเลขก่อนเอาไปคำนวณ และเทียบ === ให้เห็นว่า "20" === 20 เป็น false เพราะคนละชนิดข้อมูล

ex3-calculator.js
เก็บค่าคงที่ (เกณฑ์คะแนนเต็มต่างๆ) และคะแนนดิบแต่ละส่วนไว้ในตัวแปรแยกกัน ไม่ใช้ magic number ฝังตรงๆ ในสูตร
จากนั้นคำนวณ: แปลงคะแนน workshop ตามสัดส่วน (raw/60*20) รวมคะแนนทุกส่วน แปลงเป็นเปอร์เซ็นต์ หาว่ายังขาดอีกกี่แต้มถึงจะได้ 80 คะแนน แล้วพิมพ์สรุปผลด้วย template literal พร้อม .toFixed(2) ให้ทศนิยม 2 ตำแหน่ง

ex4-grade.js
ฟังก์ชัน toGrade(score) ใช้ if/else if ไล่เช็คคะแนนจาก มากไปน้อย เหตุผลสำคัญคือ JS เช็คเงื่อนไขจากบนลงล่างและหยุดทันทีที่เจอเงื่อนไขแรกที่เป็นจริง
ถ้าเรียงจากน้อยไปมากจะตัดเกรดผิดหมด (เช่น 95 จะโดนจับเป็นเกรดต่ำสุดก่อน) มีการดักคะแนนนอกช่วง 0-100 ไว้ด้วย แล้วลูปทดสอบด้วยชุดคะแนนตัวอย่างหลายเคส

ex5-switch.js
ใช้ switch สองตัว: ตัวแรกหาราคาตามชื่อเมนู (จงใจใช้เทคนิค fall-through — ปล่อยให้ 3 case ที่ราคาเท่ากันไหลไปทำงานร่วมกันโดยไม่ใส่ break คั่น เพื่อไม่ต้องเขียนโค้ดซ้ำ)
ตัวที่สองหาตัวคูณราคาตามขนาด (ธรรมดา/พิเศษ/จัมโบ้) แล้ววนลูปรายการสั่งอาหาร คำนวณราคาต่อรายการ (ราคาเมนู × ตัวคูณขนาด × จำนวน) และรวมยอดบิลทั้งหมด มีการใส่เมนูที่ไม่มีในระบบ (ตำปลาร้า) ไว้ทดสอบ default case ด้วย

ex6-login.js
ฟังก์ชัน login() ตรวจสอบเงื่อนไขตามลำดับความสำคัญด้านความปลอดภัย: 
(1) username/password ก่อน — ใช้ || เพื่อบอกว่าผิดทั้งคู่รวมกันเป็นข้อความเดียว ("ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง") ไม่บอกแยกว่าผิดตรงไหน
(2) เช็คบัญชีถูกระงับด้วย === แบบเข้มงวด
(3) เช็คอายุ
(4) สุดท้ายค่อยเช็ค role เพื่อคืนสิทธิ์ที่เหมาะสม
ทดสอบ 6 เคสครบทั้งกรณีสำเร็จและกรณีผิดพลาดแต่ละแบบ ท้ายไฟล์มีคำตอบอธิบายว่าทำไมต้องเช็ค username/password ก่อนเช็ค role 
และทำไมห้ามเอาการเช็คอายุขึ้นไปเช็คก่อน หลักการคือห้ามเปิดเผยข้อมูลใดๆให้คนที่ยังพิสูจน์ตัวตนไม่ผ่าน เพราะจะเปิดช่องให้แฮกเกอร์รู้โครงสร้างระบบ (เช่น รู้ว่ามีเกณฑ์อายุ) ทั้งที่ยังไม่ผ่านด่านรหัสผ่านเลย
